# Ordinary NPC death-drop sharing

The producer is the authenticated client executing the native death of the NPC it owns. The killer can be a different player. Native owner identity is sealed by the existing reliable EVENT PED_DEATH; pickup manifests remain inert on SYSTEM until the server verifies the immutable original producer, vitals incarnation and NPC generation/owner epoch/death sequence. Transfer never creates another producer allowance.

This increment shares actual native firearm outputs (models 346-353 and 355-358), pickup type 4, from random-created exterior NPCs outside active missions. Cop outputs retain their stock-model restriction. It shares native model 1212/type 8 money wads for native-eligible NPC types. Cops, medics and firemen do not grant cash. Player deaths, mission-created actors, interiors, melee, thrown/heavy weapons, persistent type 22, shop/respawning pickups and collectibles remain outside this slice. This is supported ordinary NPC loot, not full native pickup parity.

Each death permits at most 13 firearm outputs (native weapon slots) and seven money wads. The legacy `cop` origin field now means ordinary NPC origin. It gains a serialized ordinal: 1-13 firearms, 14-20 money. Dedup includes immutable original producer incarnation, NPC death seal and ordinal; a new creation nonce cannot reopen a spent ordinal. Existing packet names/channels remain unchanged. The wire schema requires root's matching 0.8.0 protocol; this branch deliberately does not edit global version or packet enums.

The original A559 weapon routine caps from half of native street-ammo table words, rather than the reversed source's multiplication. We capture resulting quantities unchanged. Receive bounds are 346:15; 347/348/350/351/358:5; 349:7; 352/353:30; 355/356:40; 357:10. These are validation ceilings, never a replacement reward calculation. Money entry 0x4590F0 is a relative jump to 0x1564140. Its native amount read zero-extends a 16-bit field despite the SDK's signed declaration. Original CreateSomeMoney emits at most seven wads, each no larger than 9365; the service captures each actual quantity/position. Money scatters cumulatively; bounded exterior wads within 15 horizontal units of the sealed death are admitted. Native ground projection may change Z independently; both the original death and generated drop require finite world coordinates, without an invented Z-distance limit. The horizontal envelope permits all seven cumulative, independent native sine/cosine offsets even when earlier ground probes do not generate a wad. No invented native money or reconstructed random distribution.

Supported sealed death-context merge attempts return false before native mutation. The unchanged native death caller then takes its Generate branch with its original amount and coordinates. This creates an independent pickup lifetime and leaves prior piles/grants unchanged. Offline, ordinary and unsupported merges retain original behavior. Pool exhaustion can prevent generation; we do not fabricate a replacement resource. Pre-existing or unrelated merges still use the reviewed terminal ambiguity policy rather than re-publishing a full pile that could duplicate a prior benefit.

Every native grant checks exact current collector life, metadata, native pickup/object/pool/model identity and exterior mission eligibility before one original Update. Only the actual collector gets native resources and native collected-query flags. Money has no server ledger reward: its single native increment is observed by the existing session wallet. False-return benefits retire as UnknownAfterApply. Terminal pre-apply declines (including moving away while a grant is in flight) conservatively retire the item without benefit. Missing model/object/pool work remains inert where identity is still valid. Removed/expired held grants retain and settle exact receipts; no regrant or reopening.

Headless tests run extracted actual client/server services, actual hook bodies, original native TryToMerge body, original Pickup.cpp touch predicate and real packet serializer. They prove protocol/service behavior under recorded native doubles. A559 disk bytes validate prefixes, calling convention boundaries, native table ceilings and the special model-only CanPlayerStartMission branch. This does not prove gameplay execution or installed visibility. No PlayerHooks/SCM/NPC manager changes.

## Human gameplay checklist

- With host and guest as native producers in turn, kill an ordinary cop, civilian and armed gang member. The killer may be the other player. Both clients must see the same supported loot and corpse.
- Kill a second supported NPC near an existing same-weapon pile, including while another collector has an issued grant. Existing pile must remain unchanged; new visible output must not double-credit either collector.
- Let the other player collect a weapon or a civilian/gang cash wad. One real native benefit, one shared removal, no second wallet credit. Stock cops must never spawn invented cash.
- Repeat state/manifest/receipt replay, late join, model streaming delay, transfer before proof, producer disconnect and player/NPC slot reuse. No resurrection of retired items or stale producer benefits.
- Check ordinary/offline unsupported native pickups still behave natively. Mission/interior/persistent/melee/heavy loot is not advertised as shared.

Root owns combined build, protocol, packaging and runtime handoff; user owns gameplay testing.
