# Bounded NPC lifetime and state synchronization

This slice extends the existing NPC networking on base `5ab4976`; it does not replace native owner AI or implement arbitrary task replication. The existing task serialization hooks are disabled in `client/src/Hooks/TaskHooks.cpp`. No SDK or SCM changes, native game execution, deployment or protocol-version edits belong to this worktree.

NPC slot IDs remain 0 through 254. A server-assigned, monotonically increasing 31-bit generation distinguishes each reused slot. An explicit owner epoch distinguishes successive controllers of the same lifetime. A shared state sequence orders on-foot, driver and passenger updates. Exhausted counters fail closed. State/deletion/claim/shot operations are authenticated against the owner and lifetime; owner assignment is idempotent instead of toggling local authority. Generic PED entity operands carry generation and validate bounds on read/write; non-NPC entity operands retain zero generation and their prior wire fields.

`PED_REPLAY` and `PED_PIN` are the two new reliable EVENT names. Creation, confirmation, assignment, deletion, pin and reliable replay share EVENT ordering. State remains unreliable SYNC, with generation/epoch/sequence rejection. Server replay uses a fresh local copy with the current server time for every delivery, preventing client timestamp sorting from moving cached replay before a later spawn or assignment. The server retains the actual on-foot/driver/passenger packet, including health, armour, weapon state/ammo, area and existing vehicle fields. On-foot velocity is now encoded and applied, alongside the existing heading/movement/duck/aim state. No native pointers or opaque task objects are transmitted.

Authenticated menu/loading clients retain bounded dormant spawn/replay/assignment/pin identities. There is no authentication-time expiry: retry starts only after scripts, local player and native pool are ready, at most four queued operations per 250 ms. Failed model loading or full native pools retain the same generation and reliable state. Missing driver/passenger vehicle bindings are deferred. Newer generations and removals supersede old dormant work; stale ownership epochs cannot overwrite newer pending assignments. Constructor metadata is assigned before any early return. Unconfirmed native destruction reclaims temporary slots; late confirmation cleans up only its original server generation, preserving a newer creation token. Creation tokens never reset during Clear/retry.

Gang workers call `CNetworkPedManager::PinGangWarPedToHost(CPed*, bool)` after native `bPartOfAttackWave` assignment. An unconfirmed host actor sends an immediate creation-token pin on the same EVENT stream as creation and retains its desired pin until matching confirmation. The server resolves this form only for the authenticated current host and its exact still-owned creation token. Confirmed pin operations require the exact generation/owner epoch. Pinned actors reject claims/transfers; host departure removes them instead of claiming native wave AI migration. Root's gang service owns wave creation, native completion, territory and cancellation.

Native guest bullet effects keep the existing `PLAYER_BULLET_SHOT` to owner-side `DoBulletImpact` path. The server and native entity resolver reject reused NPC generations. Native kill attribution is not rewritten: adjacent gta-reversed `Events/EventHandler.cpp:422` passes the attacking ped type to Darkel, `Entity/Ped/PlayerPed.cpp:125/964` leaves replicas created at player IDs 2+ as PLAYER1, and `Darkel.cpp:517` can therefore provoke using the host's on-foot/location context. No fabricated kills or rewards are added.

Headless tests freeze/hash real production packets, SDK enums, `serialize.h` and actual service/constructor/handler functions. Only native objects, streaming, task effects and transport are recorded doubles. The replay ordering tests also compile the actual server `BuildPacketStream` and client `CPacketBuffer::Receive`. They are not native address/ABI or engine execution.

Every output must be new. Mutation commands are expected to fail. Final verification records source/support/extraction SHA256 values and compiler commands. The original parity suite retains all 10,368 complete input/roundtrip cases and every shorter-payload loop. Its new count is 598,807 assertions versus 464,023 previously: exactly 13 additional truncation lengths per case, from 101 added stamp/area bits. The total suffix over the original pre-parity packet is 125 bits (24 parity + 101 lifetime/area). An intermediate stricter dirt draft reported 271,927 assertions because malformed dirt did not encode; that draft was superseded. Established native dirt normalization (nonfinite to zero, finite clamped 0..15) remains before full state validation. Recorded sender/receiver tests still exercise actual unchanged bodies and every original flag combination and authority assertion.

Independent review corrections are separate from the original checkpoint. `4fa2cca` serializes the existing entity-type operand through a local int, avoiding the three padding bytes after its uint8_t enum without changing wire width/order. Forty poisoned-padding combinations add 120 actual-codec assertions; the same regression fails 52 assertions on the original source and passes in the corrected 18,339-assertion suite. `d05c20d` fixes different-car passenger transfer and same-car seat changes, rejects another actor in the target seat, and consumes sequence only after successful placement. Failed native placement retains reliable replay. The original independent passenger counterexample is imported with only its include path changed (original source hash 212F5B77724F699C3414FB6E47B6B67E4CD618073D0E0B19950D5E3B7D5A713B); it fails two of three assertions before correction and passes all three afterward. Extended actual client functions pass 37 assertions. Original checkpoint evidence does not prove these corrected bytes; the verification JSON keeps correction identities and fresh evidence separately.

Limits remain explicit: 255 active server slots; unsupported/full-capacity creation is not magically admitted. Existing native actors added before authentication are not comprehensively adopted. Generic AI task history, pathfinding choices, non-bullet combat, exact death animation/task state and full vehicle-parent lifetime generations are not provided by this slice. Non-pinned owner release can preserve an actor through an existing claim; native AI continuation after generic ownership handoff remains a runtime limitation. SCM primitive ped-parameter encoding and other legacy task formats are outside this generation extension. Fire and gang services are separate owners and need root integration. No claim of full NPC AI replication is justified.
